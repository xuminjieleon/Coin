# CoinLens 回测轮次协议

本 skill 是执行清单；完整规则以项目 AGENTS.md §7 为准，冲突以 AGENTS.md 为准。动手前先读 AGENTS.md。

## 动手前（预登记——全部写于跑数之前）

1. 协议写死在脚本 docstring：标的池、时间窗口、几何来源、费率口径、era 切片起止、验收关（默认三关：G1 合并净 totalR>0 / G2 正收益标的占比 ≥2/3 / G3 最差标的净 EV>-0.15R；其它关须预声明）
2. **零调参纪律**：生产几何/权重原封不动。调参机会已烧（币圈第 11b/13 轮、美股第 33 轮）；新调参须有新数据维度 + 重新预登记，不得以本轮结果挑参数、不得看盲段
3. 对照组（Donchian/EMA/B&H 等）参数也要预声明，占优时如实报告

## 写脚本时

4. **必须 multiprocessing 并发**（AGENTS §7.8）：每 symbol×timeframe 一个 worker，Windows 入口必须 `if __name__ == "__main__"` 保护；网络回填用 asyncio 且尊重限流；kline_cache 深层回填必须串行慢速并**核对返回根数**（burst 部分失败是登记过的坑）
5. **数字机器核验**（AGENTS §7.9）：报告会用的叙述性数字（排名/轨迹/换算/汇总）必须由脚本打印输出，文档只抄输出，不心算；换算仅限 1R=1% 固定注额
6. 输出层注意：回撤/累计类统计必须按时间排序后再算；记录缓存键含 `services/analysis/*.py` 源码哈希

## 跑完之后

7. DEVLOG.md 顶部追加该轮记录，**先写「### 说人话」小节**（范式见第三十八轮），技术明细随后
8. 文档同步：AGENTS.md §5 加条目/待办更新；涉及用户策略数字时同步 BACKTEST.md / STRATEGY.md（数字只抄机器输出）
9. 诚实纪律：失败/被否决/对照组占优，全部如实留档（先例：第二十轮 K3 否决、第四十一轮产品线终止）
